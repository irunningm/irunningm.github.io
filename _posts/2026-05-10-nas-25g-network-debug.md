本来以为是个十分钟的事——买个 USB 2.5G 网卡，插上 NAS，跑满速。结果从晚上九点折腾到凌晨一点，经历了驱动崩溃、USB 断连、内核内存分配失败、路由器交换芯片瓶颈等一系列问题。记录一下，给后来人避坑。

<!--more-->

## 背景

我有一台群晖 DS918+，原生只有两个千兆网口。最近 PC 升级了 2.5G 网卡，想让 NAS 和 PC 之间跑满 2.5G 内网速度，于是买了个 USB 2.5G 网卡（Realtek RTL8156B）。

路由器是小米 BE6500 Pro，全 4 口 2.5G，看起来完美适配。

## 第一阶段：8156B 插上去，灯不亮

把 8156B 插到 NAS 的 USB 3.0 口，驱动装好，`ip link` 能看到 `eth2`。但网线一插上去，网口指示灯就灭了。

路由器那边 `swconfig` 显示对应端口 `link:up speed:2500baseT`——路由器认为链路通了。但 NAS 侧 `ethtool eth2` 显示 `Link detected: no`。

**路由器看到链路了，8156B 自己不认。**

查 `dmesg`，发现一堆错误：

```
r8152 2-2:1.0: read type=0x0133 fail -71
r8152: Stop submitting intr, status -71
usb 2-2: USB disconnect, device number 2
usb 2-2: new SuperSpeed USB device number 3
```

USB 通信反复断连（错误码 `-71 = EPROTO`），驱动每次重新加载都失败。这时候我以为是 USB 供电不足，但后来证明不是。

## 第二阶段：驱动崩溃

试着卸载重装驱动：

```bash
sudo rmmod r8152
sudo modprobe r8152
# modprobe: FATAL: Module r8152 not found
```

群晖的 r8152 是通过套件安装的，不在标准内核模块路径里。找到了真实路径：

```bash
/volume1/@appstore/r8152/r8152/r8152.ko
```

用 `insmod` 全路径加载后，驱动起来了，但 `ifconfig eth2 up` 报错：

```
SIOCSIFFLAGS: Cannot allocate memory
```

dmesg 里还有 `free_all_mem` 的内核 WARNING。这时候我怀疑是驱动版本太旧（v2.20.1），决定升级。

## 第三阶段：驱动升级，越升越乱

从 GitHub 的 [bb-qq/r8152](https://github.com/bb-qq/r8152) 项目下载了最新的 v2.21.4-1（`_7.3` 版本），通过 `synopkg` 安装。结果 `synopkg start r8152` 直接失败，dmesg 里同样的 `free_all_mem` 崩溃。

去 GitHub Issues 一看，[#619](https://github.com/bb-qq/r8152/issues/619) 和 [#620](https://github.com/bb-qq/r8152/issues/620) 都有人报 DS918+/DS920+ 上 v2.21.4 不工作。#620 里有人提到速度协商 bug——驱动加载成功但只广播 10/100M，不广播 1G/2.5G。

回退到 v2.20.1，还是同样的 `Cannot allocate memory` 错误。

**这时候我意识到：问题不是驱动版本，是来回装/卸驱动把内核内存状态搞乱了。**

## 第四阶段：重启解决一切

一咬牙 `reboot`。重启后：

- v2.20.1 加载正常，无报错
- 升级到 v2.21.4 也正常，无崩溃
- eth2 成功 UP，`Link detected: yes`，`Speed: 2500Mb/s`

**折腾两小时的问题，一个 reboot 解决了。**

教训：在 Linux 上反复 `rmmod`/`insmod` 内核模块，尤其是在 Synology DSM 这种非标准环境里，很容易搞乱内核状态。遇到 `Cannot allocate memory` 之类的诡异错误，先重启试试。

## 第五阶段：路由器的坑

8156B 跑通了，但发现路由器也有问题。

### 端口协商卡 100M

排查过程中发现 PC 接在 LAN 2 口只协商到 100M，换到 LAN 3 口还是 100M。一度以为是 PC 网卡的问题，但 PC 端用的是 RTL8125 2.5G 网卡，一直声明支持 2500baseT。

最终经过重新插拔和重启后，PC 恢复到 2500M，路由器侧也显示 4 个口全部 2500baseT。

**根本原因：BE6500 Pro 的 2.5G PHY 自动协商不稳定。** 2.5GBASE-T 对线对质量、回波、串扰的判断比 100M 敏感得多。某次协商训练失败后，端口会卡在 100M 不动，直到重新插拔或重启才能恢复。这是 BE6500 Pro 的已知问题，网上有类似反馈。

### 5Gbps 总带宽瓶颈

更关键的发现：**4 个 2.5G 口共享 5Gbps 总带宽**。

拆机资料显示，BE6500 Pro 用的是 **QCA8386** 交换芯片，只有 2 个 HSGMII 上联口，总吞吐量被限制在 5Gbps。也就是说，多设备同时传输时，每个口分到的带宽远不到 2.5G。

相比之下，用 **QCA8084** 芯片的路由器（如小米路由器 7000）是 4 口共享 10Gbps，每个口都能独立跑满 2.5G。

### 路由器 UI 显示 bug

路由器管理界面显示端口速率是 1000M，但 `swconfig` 实际显示 2500M。UI 的锅。

## 遗留的坑：8156B 随机掉线

跑通 2.5G 后没多久，8156B 又掉了。`dmesg` 里同样的 `-71` (EPROTO) USB 协议错误，驱动反复崩溃重连。

这个问题在冷启动后（NAS 重启）能稳定运行一段时间，但运行几小时后就会复发。目前不确定是 8156B 硬件缺陷还是群晖 918+ USB 控制器的兼容性问题。建议把 8156B 插到 PC 上测试一段时间，排除网卡本身的问题。如果 PC 上也掉，那就是网卡有毛病，换个品牌试试。

**重要提示：原生千兆口始终保持连接**，作为备用管理通道。8156B 掉线时至少还能 SSH 进去操作。

## 遗留的坑：BE6500 Pro 的 PHY 协商不稳定

排查过程中还发现了一个更隐蔽的问题：**BE6500 Pro 的 2.5G 端口会随机卡在 100M**。

具体表现：PC 的 2.5G 网卡一直声明支持 2500baseT，路由器端也支持，但两边最终却落到 100baseT。换口、换线都没用，只有重新插拔或重启才能恢复。

这不是个案。用 Codex 排查后判断：这是 2.5GBASE-T 物理层自动协商的训练失败问题。2.5G 对线对质量、回波、串扰的判断比千兆敏感得多，某次训练失败后端口会卡在低速不动。

再加上 QCA8386 交换芯片的 5Gbps 总带宽瓶颈，多设备同时传输时每个口分到的带宽远不到 2.5G。

**这些问题的根本原因是路由器的交换芯片方案太省成本。** 如果你对内网速度有要求，建议在路由器和高速设备之间加一个 2.5G 交换机：

```
光猫 (2.5G) ─→ 小米 BE6500 Pro
                  ├─→ LAN 口 ─→ 2.5G 交换机 ─→ PC
                  │                          └→ NAS (8156B)
                  └─→ LAN 口 ─→ 千兆交换机 ─→ 电视 / Apple TV / PS5
```

PC 和 NAS 接在 2.5G 交换机上，两者之间直接交换不过路由器，既绕过了 5Gbps 瓶颈，也避开了路由器端口协商不稳定的问题。2.5G 交换机 150-200 元，比换路由器划算得多。

## 总结：踩坑清单

| 坑 | 原因 | 解决 |
|----|------|------|
| 8156B 灯灭、链路起不来 | USB 通信错误导致驱动反复崩溃 | 卸载重装驱动 + 重启 |
| `Cannot allocate memory` | 反复 rmmod/insmod 搞乱内核内存状态 | **重启 NAS** |
| 驱动 v2.21.4 崩溃 | 一开始误判为内核不兼容，实际是内存状态问题 | 重启后正常 |
| LAN 口协商卡 100M | BE6500 Pro 2.5G PHY 训练失败后退速 | 重新插拔/重启恢复 |
| 多设备降速 | QCA8386 交换芯片 5Gbps 总带宽瓶颈 | 加 2.5G 交换机 |
| UI 显示 1000M | 路由器固件 bug | 以 swconfig 为准 |

**核心教训：**

1. **先重启再排查**。来回折腾驱动之前，先 reboot 排除状态污染。
2. **查交换芯片型号**。买路由器不能只看"全 2.5G 口"，要看交换芯片是 QCA8084（10G 上联）还是 QCA8386（5G 上联）。
3. **2.5G 交换机是刚需**。只要内网有多设备需要高速互联，加一个 2.5G 交换机比换路由器便宜得多。
4. **群晖的第三方驱动装在非标准路径**。`modprobe` 找不到，得用 `insmod /volume1/@appstore/r8152/r8152/r8152.ko` 全路径加载。
5. **2.5G 协商比千兆脆弱**。2.5GBASE-T 对线缆质量更敏感，协商失败会退到 100M 且卡住。遇到降速先重新插拔，别急着换硬件。
